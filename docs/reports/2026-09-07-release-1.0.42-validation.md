# v1.0.42 게시 전 검증

## 검증 범위

v1.0.41 이후 모딩 및 퀘스트 검색 변경과 이번 부품 필터 프리셋을 함께 검토했다. 사용자 개인 패치 `previous-updater-tag-fix.patch`는 수정하거나 배포에 포함하지 않는다. 업데이트 서명 신뢰 기준과 GitHub 릴리즈 워크플로의 보안 검증은 완화하지 않는다.

- 단위·컴포넌트: 73개 파일, 875개 통과.
- 데이터 계약: 8개 통과. 릴리즈 계약·보안·번들 테스트: 36개 통과.
- v1.0.42 프로덕션 빌드, 전체 ESLint, 타입 검사 통과. 기존 큰 JS 청크 경고는 유지된다.
- 전체 앱 E2E 및 프리셋 편집 E2E 통과. 320/768/1024/1440/1920px에서 편집·저장·즐겨찾기·복원·실행취소·가격·성능·확대·각도 적용을 별도 headless 브라우저로 검증했다.
- 필터 프리셋 E2E: 반동/인체공학 우선순위, 조건 저장·복원·덮어쓰기·삭제, 새로고침, 키보드와 좁은 화면 통과. 외형 서비스 실제 요청은 0회.
- 의존성 감사: 알려진 취약점 없음.

## 게시 전 추가 발견과 수정

1. **큰 정상 미리보기 요청 거부**: JSON 입력은 64KiB를 허용하지만 하위 PowerShell 본문 읽기는 8KiB로 제한됐다. 8,193/65,536바이트의 정상 JSON이 400으로 실패하는 RED를 확인한 뒤 하위 읽기 상한을 일치시켜 200을 확인했다. 다른 JSON endpoint의 기본 8KiB 제한과 종료 endpoint의 별도 8KiB 검사는 유지한다.
2. **오류를 가리는 연결 정리 예외**: 응답의 선언 크기 또는 읽은 크기가 초과한 경우, 정리 단계의 예외가 원래 `InvalidDataException`을 덮을 수 있었다. 두 경로를 독립 재현한 뒤 최초 오류를 보존하고 모든 자원의 정리와 요청 취소를 시도하도록 수정했다. 원래 오류가 없는 정리 실패는 계속 보고한다.
3. **Windows 조기 거부 테스트의 전송 경합**: 상한을 넘는 본문/헤더 전체를 업로드하면 읽히지 않은 꼬리 때문에 응답 전달 전에 TCP RST가 발생할 수 있었다. 본문은 `Content-Length: 65537` 헤더만, 헤더 상한은 종료 문자가 더 들어갈 수 없는 정확히 16,384바이트를 전송하여 즉시 400/431과 완전한 응답을 검증한다. 2초 제한을 두며, 빈 응답·연결 초기화를 성공으로 취급하지 않는다.

수정 후 미리보기 Node·Windows 통합 25개와 실행기 회귀 12개가 모두 통과했다. 응답 크기 제한·출처 검사·429 대기·타임아웃과 잘못된 응답의 502 분류를 유지한다.

## 배포 확인

이 기록은 로컬 검증이며 GitHub 게시 완료를 뜻하지 않는다. 최종 커밋의 CI 성공 후 해당 커밋에 v1.0.42 태그를 붙이고, Release 워크플로의 Windows 품질·패키징·서명·불변 게시 게이트를 통과해야 한다. 최종 확인 대상은 최신 릴리즈 표시, Direct/Static/Source ZIP, SHA256SUMS, 업데이트 manifest 및 RSA 서명 총 6개 파일이다.
