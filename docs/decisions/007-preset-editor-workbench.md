# 인게임형 프리셋 편집기

상태: 로컬 구현. 릴리즈하지 않음. 날짜: 2026-09-07.

후속 결정: 사용자의 별도 릴리즈 요청에 따라 v1.0.42에 포함한다. 아래의 릴리즈 제외·미게시 기록은 초기 구현 당시의 범위이며, 배포 시 주의점은 [v1.0.42 안내](../releases/v1.0.42.md)를 따른다.

## 목표와 범위

사용자가 제공한 프리셋 화면을 기준으로 실제 편집 가능한 웹 작업대를 만든다. 큰 총기 표시 영역, 장착 부품 이미지 카드와 연결선, 중첩 슬롯 탐색, 호환 부품 선택, 프리셋 저장과 되돌리기가 하나의 흐름이어야 한다. 기존 가격·성능·즐겨찾기·저장 데이터는 보존한다.

총기 3D 모델을 확보한 것으로 가장하지 않는다. 현재 외부 생성 서비스는 지원되는 조합의 각도별 정지 이미지를 제공한다. 개략 연결선과 실제 모델 좌표를 구분하고, 실패한 조립 외형에 기본 사진을 현재 결과처럼 표시하지 않는다. 게임 설치·실행·프로세스 조작·보호 우회·릴리즈는 범위 밖이다. 실제 자유 회전 및 전체 최신 모델 지원은 자산과 변환 검증이 필요한 미충족 범위로 명시한다.

## 기술과 규칙

- React 19.2 / TypeScript 5.9 / Vite 8, 기존 CSS 토큰과 접근성 패턴 사용.
- 앱 `src/features/modding`, 조립 도메인 `src/domain`, 기존 저장 서비스 `src/services`를 재사용한다.
- 불변 상태 변경, 부모 인스턴스 + 슬롯 ID로 선택을 식별한다. 반복 장착을 합치지 않는다.
- 새 외부 의존성 없이 우선 구현한다. 네트워크 생성은 기존 선택적 활성화와 지연·캐시·호출 제한을 보존한다.
- `POST /api/modding/preview`는 기존 `{root, angle}` 구조를 유지하며 `angle`을 -180~180 범위의 15도 간격 정수로 확장한다. 잘못된 값은 보정하지 않고 거부하며, Node·포터블·프런트 검증을 일치시킨다. UI의 각도 슬라이더는 초안일 뿐이며 **각도 적용** 또는 빠른 각도 버튼에서만 요청한다.
- 확대는 100~200%의 로컬 2D 변환이다. 일부가 잘릴 수 있음을 알리고 확대·측면 외 각도에서는 개략선을 숨긴다. 별도 크게 보기 창은 현재 이미지를 재사용하며 요청하지 않는다.
- 이전 updater patch와 지도·퀘스트·업데이트 영역은 수정하지 않는다.

## 순서와 검증

1. 공개 자료 조사: 기존 공급자와 SPT/관련 제작자 공개 코드를 검토하여 실제 지원과 구현 가능성을 기록한다. 게임 파일 접근 없이 진행한다.
2. 슬롯 캔버스: 개별 슬롯 카드를 이미지 위·아래에 배치하고, 장착/빈 슬롯과 부품 이미지를 구분한다. 슬롯 필터·페이지 이동으로 많은 슬롯도 가리지 않는다. 선택된 슬롯이 숨겨지지 않으며 중첩/반복 슬롯이 정확히 선택되어야 한다.
3. 작업대: 큰 중앙 외형 + 옆 부품 선택 패널로 재배치하고, 장착 트리와 후보 선택을 명확히 전환한다. 좁은 사이드 패널에서는 세로로 배치한다. 이미지 확대는 2D 확대임을 명시한다.
4. 편집 안전성: 부품 교체/제거/초기화/프리셋 불러오기를 실행취소·다시실행으로 복원한다. 이름 붙인 프리셋은 명시적 저장 전 변경하지 않는다. 기본 포함 부품 중복 비용을 방지하는 기존 계산을 유지한다.
5. 실브라우저: 사용자 사이드 패널에 로컬 테스트 주소를 열고 변경을 반영한다. 테스트는 별도 브라우저 데이터로 진행하고 사용자 게임/기존 저장 빌드를 건드리지 않는다.

검증 명령: `pnpm exec vitest run tests/features/weapon-modding-page.test.tsx tests/features/weapon-preview.test.tsx`, 추가 슬롯·히스토리 단위 테스트, `pnpm typecheck`, `pnpm lint`, `pnpm build`. 브라우저 검증은 320/768/1024/1440/1920px에서 겹침·가로 넘침·키보드 접근·부품 교체 및 저장 복원을 확인한다. 조립 이미지 통신 테스트는 모의 응답과 실제 제공자 소수 요청을 구분한다.

## 완료 기준

- 부품 카드를 누르고 후보를 골라 실제 구성·이미지 카드·성능·추가 구매비가 함께 갱신된다.
- 부품을 바꾸면 하위 슬롯을 계속 찾아갈 수 있고, 반복 슬롯/필터/빈 슬롯이 누락되지 않는다.
- 실행취소와 다시실행이 동일한 조립 구성과 계산 결과를 복원한다.
- 프리셋/즐겨찾기와 기존 브라우저 저장 자료가 유지된다.
- 외형 지원 한계와 개략 좌표가 명확하며, 게임과 동일한 3D 구현이라고 허위 표시하지 않는다.

## 선택한 구조와 대안

게임의 Unity 프리셋 화면을 웹에 그대로 실행할 수 있는 완성 SDK와 최신 전체 자산을 확보하지 못했다. 따라서 공개 소스는 구조와 동작을 이해하는 근거로 사용하고, 제품 코드나 게임 자산을 복사하지 않았다. [자료 조사 및 실제 생성 검증](../reports/2026-09-07-preset-editor-research.md)에 출처와 미지원 범위를 기록한다.

세 열을 항상 나열하면 중앙 총기가 작아지므로 큰 외형과 전환 가능한 옆 패널의 두 열을 선택했다. 개별 카드는 부모 인스턴스와 슬롯 ID를 보존하고, 최대 14개 및 화면 폭별 페이지로 나눈다. 필터와 페이지를 바꿔도 총기가 움직이지 않도록 카드 행을 예약한다. 1100px 이하에서는 세로 배치하며 선택 결과로 이동한 뒤 **총기 부위로 돌아가기**를 제공한다.

히스토리는 최대 40회, 세션 내 불변 조립 스냅샷만 저장한다. 가격·필터·PVP/PVE 변경과 이름 붙인 저장은 편집 기록에 넣지 않는다. 무기·카탈로그 버전 변경은 기록을 분리하며, 같은 총기의 초기화·프리셋 불러오기는 되돌릴 수 있다. 기존 저장 형식은 바꾸지 않고 읽을 수 없는 저장 문자열에는 쓰기를 거부하여 원본을 보존한다.

## 검토 중 수정한 결함

- 충돌 부품 자동 해제 안내를 조립 스냅샷에 결합하고 Undo/Redo에서 지워, 복원된 구성과 이전 안내가 충돌하지 않게 했다.
- 좁은 화면에서는 선택 패널이 능력치·가격 아래에 있어 클릭 반응을 볼 수 없던 문제를 실제 브라우저로 재현하고 이동/복귀 경로로 해결했다.
- 하위 슬롯 선택 콜백을 작은 표시 컴포넌트로 분리해 React 컴파일러의 별칭 분석과 기존 후보 메모를 양립시켰다. 검사 규칙과 메모를 제거하지 않았다.
- 손상·미지원 저장 자료를 빈 저장소로 취급해 자동 저장 시 덮어쓰던 기존 결함을 수정했다.

게임과 같은 자유 회전 3D, 최신 모든 부품의 외형 생성, 정확한 모델 부착점은 미충족 범위다. 이 로컬 편집기 구현과 구분한다.

## 최종 검증 및 재현

- `pnpm exec vitest run --maxWorkers=1`: 71개 파일, 814개 테스트 통과. 변경 전 실패를 확인한 카드·히스토리·각도·저장 보존 회귀 포함.
- `pnpm test:e2e`: 별도 headless 브라우저의 기존 전체 앱 흐름 통과. 모딩 검증은 새 전환 패널 및 페이지별 카드 전수 비교로 갱신했다.
- `node e2e/preset-editor.mjs`: 1920/1440/1024/768/320px, 부품 교체→카드 이미지→성능→추가 구매비, 실행취소/다시실행, 저장/즐겨찾기/새로고침, 좁은 화면 왕복, 확대 및 각도 적용 흐름 통과. 외형 요청은 모의 응답이며 실요청 검증과 구분한다.
- 실제 외부 생성은 알려진 기본 M4의 90°/180° 총 2회 성공. API 18개 및 포터블 통합 3개 테스트 통과. 상세 입력과 한계는 조사 보고서 참조.
- 전체 ESLint, TypeScript, 프로덕션 빌드 통과. 기존 단일 번들의 500kB 크기 경고와 jsdom 외부 페이지 이동 미구현 안내는 남아 있다.
- 스크린샷: `output/playwright/preset-editor-{320,768,1024,1440,1920}.png`, `preset-editor-zoom.png`. 실제 렌더한 화면을 확인했다.
- 사이드 패널: `http://127.0.0.1:41754/#/modding?weapon=5447a9cd4bdc2dbd208b4567`. 현재 사용자의 저장 프리셋과 초안은 읽기만 하고 테스트는 별도 저장소에서 수행했다.
- 커밋/푸시/릴리즈/버전 변경 없음. 게임 파일 접근 및 실행·입력 조작 없음.
