# 조립 총기 미리보기와 부위 탐색

## 사용자 요구와 구현 범위

부품 교체 시 부품 카드뿐 아니라 중앙 조립 총기의 외형도 변경한다. 게임 창, 입력 장치, 게임 파일 또는 실행 중인 게임 프로세스에 접근하지 않는다. 릴리즈하지 않고 로컬 테스트 화면에서 검증한다.

- 최대 10개의 기능별 부위 카드에 장착 부품 이미지를 표시한다. 하위·반복·빈 슬롯은 선택 부위의 목록과 기존 전체 트리에서 모두 접근할 수 있다.
- 연결선은 검증된 모델 좌표가 아닌 **개략 부위 안내**다. 회전된 이미지에서는 위치 오해를 막기 위해 선을 숨긴다.
- 선택적으로 외부 조립 이미지 생성을 켤 수 있다. 처음에는 기본 외형이며, 활성화 전 외부 전송 내용을 안내한다. 전송 데이터는 총기·부품 ID, 장착 구조 및 각도뿐이다. 프로필 이름, 퀘스트, 게임 로그 및 개인정보는 전송하지 않는다.
- 활성화하면 부품 변경을 1.5초 모아 갱신한다. 정면/좌우 각도별 정지 이미지를 제공하며, 즉각적인 자유 회전 3D 모델이라고 표시하지 않는다.
- 이전 빌드의 이미지는 새로운 빌드의 미리보기로 표시하지 않는다. 로딩, 연결 실패, 지원되지 않는 슬롯, 호출 제한, 이미지 표시 실패를 명시하고 기본 이미지로 복귀한다.

## 인터페이스

로컬 개발 서버 및 포터블 서버: `POST /api/modding/preview`

입력: `{ root: BuildNode, angle: -30 | 0 | 30 }`. 노드에는 `instanceId`, `itemId`, 선택적 `slotId`, `children`만 사용한다. 출력: `{ imageUrl: dataImageUrl }`. 오류: `{ error: { code, message, retryAfterSeconds? } }`.

외부 서비스는 고정 HTTPS 제공자만 허용한다. 부모 아이템별 슬롯 조회에서 24자리 슬롯 ID를 정확히 일치시켜 실제 슬롯 이름으로 변환한다. 동일 부품의 반복 장착 및 부모 관계를 보존한다. 요청·응답 크기, 깊이, 노드 개수, 시간과 캐시를 제한한다. 리디렉션을 따라가지 않으며 요청을 합치고 호출 제한 시 자동 재시도하지 않는다. 기존 서버의 동일 출처 방어를 유지한다.

## 조사 근거 (2026-09-07)

- [SPT Modules](https://github.com/sp-tarkov/modules): 기존 EFT 클라이언트에 적용되는 플러그인 구조. 웹용 전체 모델 SDK로 취급하지 않는다.
- [SPT 구조 설명](https://github.com/sp-tarkov/wiki/blob/main/How_SPT_Works.md)
- [Tarkov Image Generator](https://image-gen.tarkov-changes.com/build): 공개 클라이언트가 사용하는 일반 HTTP 생성 요청을 확인했다. `/api/item-slots/{itemId}`, `/api/generate-build-rotated`, `/api/images/{key}`를 이용한다. 쿠키·인증·브라우저 위장 없이 일반 생성 및 회전 생성 요청이 성공했다. 공식 안정성·호출량 보장은 확인되지 않았으므로 실험적 선택 기능으로 격리한다.
- [EFTForge](https://github.com/SouthHorizons76/EFTForge): 조립 이미지와 슬롯 탐색의 참고 사례. 해당 프로젝트의 브라우저 위장·보호 우회 방식은 가져오지 않는다.

## 검증 기준

모든 번들 총기의 슬롯 보존, 반복 슬롯의 정확한 선택, 부품 이미지 변경, 기본 비활성 상태의 무통신, 변경 지연, 역순 응답 무시, 오류 시 오래된 외형 제거, 각도 갱신, 서버 입력·출처·응답 검증, 캐시·호출 제한을 테스트한다. 실제 브라우저에서 총기 기본/변경 이미지 및 각도 차이를 확인하되 게임 창을 조작하지 않는다. 모델·부품 전체에 대한 렌더링 성공은 개별 검증 전 보장하지 않는다.

## 검증 결과

- 화면·도메인 테스트 66개 파일 / 769개 통과. Node 미리보기 테스트 17개, 포터블 미리보기 통합 테스트 3개, 기존 가격 API 회귀 테스트 및 포터블 실행기 테스트 12개 통과.
- 기존 전체 headless E2E 통과: 320/768/861/1024/1221/1440px, 카드 겹침·이미지 영역 초과 없음, 중첩 슬롯 보존, 성능→가격 순서와 후보 수치 열 정렬, 기본 상태 생성 요청 0건.
- 실제 개발 서버에서 M4A1 조립 PNG 표시, +30도 각도 이미지 표시, MOE 손잡이→DLG-138 FDE 교체 시 중앙 손잡이 모양·색상 및 이미지 내용 변경 확인. 시험 후 원래 손잡이로 복원했다.
- 실제 포터블 서버에서 M4A1 + 기본 손잡이를 한 번 생성하여 HTTP 200 / PNG 64,732바이트 / 약 2.9초 확인. 임시 서버와 자료는 정리했다.
- 빌드·ESLint 통과. 기존 번들 500KB 경고 및 jsdom의 외부 페이지 이동 미구현 안내는 남아 있다.

재현 명령: `pnpm test:modding-preview`, `pnpm test:e2e`, `pnpm build`, `pnpm lint`. 테스트용 개발 서버는 기존 `pnpm dev` 경로를 사용한다. 포터블은 Node 설치 없이 자체 백그라운드 처리로 미리보기를 제공한다. 정적 호스팅만 있는 환경에는 이 로컬 API가 없으므로 기능 미지원 안내를 표시한다.
